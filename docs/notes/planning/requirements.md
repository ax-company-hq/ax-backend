### 1-1. 표기 규칙

| 표기 | 의미 |
|---|---|
| **필수 / 선택 / 이후** | 필수 = MVP(10/27 기획발표·시나리오 A)에 반드시 있어야 함, 선택 = 필수가 전부 끝난 뒤, 이후 = MVP 이후. **필수가 끝나기 전에는 선택에 손대지 않는다** |
| **필수(조건부)** | 평소엔 쓰지 않지만 연동 버스·LLM이 없을 때 반드시 동작해야 하는 대체 경로 |
| ID 체계 | `FR-<그룹>-NNN` 기능, `NFR-<분류>-NNN` 비기능, `IF-<구분>-NNN` 인터페이스, `DR-NNN` 데이터, `CON-NNN` 제약, `AS-NNN` 가정·미결. 그룹 안 연속 번호, 중복 없음 |
| 수용 기준 | G(Given 전제) / W(When 행위) / T(Then 기대 결과) |
| 근거 | 구성안 장·절(예: 구성안 5-2), 공통안 장(공통안 12장), 규칙 ID(SAFE-n, 5-2), 결정 ID(AS-T01), 프로토타입 파일(`data.ts`) |
| 담당 | 주담당(부담당). 기획개발은 노예진 단독이라 부담당 없음 |
| **상태** (이 문서 추가 열) | **✅ 완료(프로토타입)** = `planning-web`에서 목 데이터로 동작 확인(AS-T01). **✅ 완료(백엔드 #101)** = [v0.6] ax-backend PR #101(10/22 dev 머지) 코드·테스트(`agents/planning/tests` 72개 통과)로 확인. **⬜ 미착수** = 코드 없음. **⏸ 대체됨** = [v0.8] 다른 요구사항으로 대체되어 더 구현하지 않음(괄호에 대체한 ID). 실제 에이전트 서버로 옮기는 일은 FR-AG가 따로 맡는다 |
| [제안] | 구성안에 없고 작성자가 보완을 제안. 요구사항 아님, 팀 결정 전 구현 대상 아님 |
| [가정] | 명시가 없어 가장 자연스러운 해석을 적은 것. 9장에 다시 모음 |
| [v0.2] / [v0.3] / [v0.4] / [v0.5] / [v0.6] / [v0.7] / [v0.8] / [v0.9] | 해당 버전에서 생긴 부분 (v0.1은 최초판이라 표시 생략) |
| [DIF-n] | 차별점 태그 (2-7). **DIF-1** 문서 중심 양방향 추적(1a 코드 역추적 [v0.2]) / **DIF-2** 변경 요청 처리 허브(2a 중복·분류, 2b 간단 요청 무인 처리·일반 요청 무클릭 진행 [v0.8], 2c 자동 처리 범위 학습 [v0.2]·교차검증 승인과 사후 감사 [v0.7]·관찰 기반 학습 [v0.8]) / **DIF-3** 다른 부서 에이전트 연결(3a 인사운영 개선 루프, 3b 장애 연동) |
| `(TODO: 추후결정)` | 팀 미결 항목. 임의 기본값으로 확정하지 않고, 기한이 지나도 자동 확정되지 않음. 이 표기가 든 수용 기준은 "결정된 값으로" 판정 |

## 2. 시스템 개요와 범위

### 2-1. 시스템 목적

기획개발팀에 들어오는 변경 요청을 받아 기획서를 만들고, 그 문서를 원본으로 작업·PR·대화·결정을 한 곳에 묶는 프로젝트 매니징 자동화 시스템이다 (구성안 1장). **[v0.7]** 기획서 확정과 생성 PR 머지는 조건을 만족하면 자동이고, 위험 건은 다른 검증자가 교차검증하며, 사람은 사후 감사·기준 끄기와 되돌릴 수 없는 일만 맡는다 (AS-T14). **[v0.8]** 일반 요청도 접수부터 머지 검사까지 사람 클릭 없이 이어 가고, 다른 부서 몫(질문 답·교차검증 판단·넓히기 판단)은 그 부서가 보낸다 (AS-T15). 상태를 바꾸는 처리는 모두 안전 레이어(`execute()`)를 통과한다. 화면 표시만 고치는 간단한 요청은 사람 손을 거치지 않고 머지·회신까지 끝낸다 (AS-T03). 장애가 나면 관련 PR 후보를 회신하고 문단에 장애를 표시하지만 원인 판정·롤백은 하지 않는다 (구성안 3장).

9. **[완료] [v0.8]** 시뮬레이터에서 변경 요청 1건을 보내면 요청 탭 맨 위에 생기고, 흐름바가 접수 → 기획 → 작업 → 처리로 실제 상태가 바뀔 때마다 채워지며, 기획서 질문 답·교차검증 판단은 다른 부서(시뮬레이터)가 보낸다 (FR-PR-010, FR-FE-017, FR-SPEC-009).

### 2-5. 제외 범위

- DejaFix A2A 래퍼(`infra`, `agents/infra-dejafix/`)는 같은 담당의 별도 모듈이라 이 문서에서 뺀다. 이 문서에는 infra와 주고받는 인터페이스(IF-INT-A2A)만 둔다.
- 원인 판정·롤백·재시작(infra), 결정 카드 판정·회사 기억 저장(hr·memory), 기각 안 판정(hr ②), 주문·결제 원천 데이터(판매 사이트), 정산 기준표(재무) (구성안 3장 "하지 않는 것").
- 노션·슬랙 재구현. 시연은 내보낸 파일 가져오기, 실제 연결은 GitHub만 (구성안 14장 11).
- **[v0.5]** "우리 부서가 참여한 사건"(대시보드 공통 화면) 메뉴는 뺐다(AS-T12). 사건은 작업 > 사후관리와 소통 > 에이전트 대화에서 보고, 예전 주소는 들어온 요청으로 돌린다. "<고객사> 바로가기"는 판매 사이트(ax-frontend shop-web, 재헌)를 새 탭으로 여는 링크다.
- 정리 문서 "내보내기"는 자리만 있다 (FR-LT-002).
- **[v0.5]** 규정·자료의 텍스트 추출·색인·근거 인용(RAG)과 서버 저장은 이후다 (FR-KB-004·005). 지금은 파일 내용을 저장하지 않는다.

### 2-6. 장기 로드맵 (요약)

L0 프로토타입(완료) → L1 시나리오 A 필수 skill 3개 + 공통 8항목 (FR-AG-001~005) → L2 시나리오 A 무인 3회 성공 뒤 요청 → 기획서 → PR 파이프라인 실제 구현·GitHub 실연결 (공통안 12장, FR-AG-007·008) → L3 화면을 실제 API·SSE로 전환하고 시뮬레이터는 개발 도구로만 (FR-AG-006) → L4 노션·슬랙 실연결 (FR-LT-001).

**연결 지점 공통 규칙 (planning 소관에 적용, 다른 부서에는 [제안])**
- 연결 부품만 프로그램 이름을 안다. 도메인·핸들러·계약은 프로그램 이름을 모른다(NFR-EXT-003과 같은 방식).

- 쓰기는 `execute()`를 지난 뒤에만 한다. 연결 부품이 지원하지 않는 쓰기는 사람에게 넘기는 읽기 전용 모드로 내려간다(FR-AG-013과 같은 방식).
