# planning 에이전트 설계
1. 누구의 어떤 일을 대신하나 (하루 일 3가지): 고객사 기획·개발 담당의 일을 대신한다.
   - 다른 부서 요청을 받아 같은 요청은 묶고 기획서(SPEC)로 정리한다.
   - 확정된 기획서를 작업으로 나눠 PR을 만들고, 검증을 거쳐 dev에 머지한다.
   - 요청이 끝나거나 기각되면 요청 부서에 결과를 알리고, 장애 때는 직전 PR을 찾아 사건에 연결한다.
2. 스스로 판단하는 것 / 사람(safety 큐)에게 넘기는 것:
   - 스스로: 중복 요청 연결, 기획서 초안·질문, 가드레일(100줄·5파일) 안 간단 요청의 자동 머지, AI 교차검증을 통과한 PR 머지, 관찰 근거가 쌓인 자동 처리 규칙 제안.
   - 넘기는 것: 되돌릴 수 없는 요청(결제 데이터 삭제 등), 보호 경로(#203) PR 중 safety AI 1차 판단(#110)에서 사람 확인으로 올라온 건, 가드레일 밖으로 자동 처리 범위를 넓히는 규칙.
   - 원칙: 사람의 사전 승인 대신 AI 교차검증 + 사람 사후 감사. 모든 판단은 근거와 함께 기록한다.
3. 다른 부서에게 받는 요청 (누가·언제·무엇) = skill 목록:
   - `create_ticket`: support·marketing·finance가 변경 요청이 생길 때, hr·data가 반복 패턴으로 개선 초안을 만들 때.
   - `find_related_prs`: data·infra·orchestrator가 이상·장애 구간 직전 머지된 PR을 찾을 때.
   - `link_incident`: orchestrator가 사건을 열고 관련 PR·기획서 문단을 연결할 때.
   - `verify_rollback_target`: safety가 infra `rollback_deployment`(B)를 검증할 때.
   - `list_in_progress`·`verify_handover`: hr가 담당자 인수인계 때 진행 중인 일을 확인할 때.
4. 다른 부서에게 하는 요청 (누구에게·무엇을):
   - 요청 부서(support·hr·data): 요청을 닫을 때 `receive_change_result`로 완료·기각 결과(#293, #318).
   - safety: PR·자동 처리 규칙의 등급 판정과 보호 경로 1차 판단.
   - hr: 사건·결정 기록(`record_case`).
   - 요청 부서: 기획서에 근거가 부족할 때 질문.
5. 기억해야 하는 것 (memory 부서와 연결): 요청·기획서·PR 처리 이력, 반복 요청 패턴, 자동 처리 규칙과 그 관찰 근거(관찰 n건·결과), 기각 사유.
6. 잘하는지 보는 지표: 요청에서 첫 PR까지 걸린 시간, 사람 손 없이 끝난 요청 비율, 머지 뒤 롤백·재수정 비율, 결과 통지 누락 0건.
