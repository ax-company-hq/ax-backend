# 재무 AI 관리자 사용법

담당: 태윤 · 화면: 대시보드 → 상단 메뉴 **재무 AI** (`http://localhost:3001/finance`)

## 한 줄 요약

재무 AI는 쿠폰, 환불, 판매자 정산처럼 **돈이 나가는 일을 한 번 더 확인**합니다. 기준을 조금 넘는 건도 **재무 AI가 자료를 보고 대신 결정**하고, **아주 큰 금액이나 판단할 자료가 없는 건만 관리자에게 넘어옵니다.** 관리자가 할 일은 화면 맨 위 **"지금 사람이 결정할 일"**을 보고 [진행] 또는 [멈춤]을 누르는 것입니다.

## 재무 AI가 일하는 방식

다른 AI(마케팅, 고객지원 등)가 돈이 나가는 일을 하려면 반드시 안전 장치를 거칩니다. 안전 장치는 요청을 세 갈래로 나눕니다.

| 갈래 | 어떤 일 | 누가 결정 |
| --- | --- | --- |
| 바로 처리 | 공지 올리기, 회사 기록 남기기처럼 돈이 나가지 않는 일 | 자동 |
| 재무 AI 확인 후 처리 | 기준 아래의 쿠폰·환불 | 재무 AI가 금액과 받을 사람을 원래 자료로 다시 계산해서 맞으면 처리, 틀리면 막음 |
| 기준 넘음 → AI가 결정 | 기준은 넘었지만 재무 AI 재량 한도 안인 쿠폰·환불, 잘못된 요청 | 재무 AI (아래 기준) |
| 사람 확인 | 재량 한도도 넘는 큰 금액, 판매자 정산 확정, 판단할 자료가 없는 건 | **관리자** |

금액은 AI가 정하지 않습니다. 정해진 계산(예: 3장 × 20,000원)과 기준표로만 판단합니다. 요청한 AI가 "괜찮다"고 적어 보내도 무시합니다.

## 재무 AI가 대신 결정하는 기준

사람 확인으로 넘어온 건이라도 아래 기준이면 재무 AI가 먼저 결정합니다. 결정과 이유는 화면의 "재무 AI가 대신 결정한 일"에 남습니다. 기준 원본: `agents/finance/src/finance_agent/ai_review_policy.toml` (사람만 변경), 켜고 끄기: `safety/src/ax_safety/rules/thresholds.toml`의 `[auto_review]`.

| 경우 | 재무 AI의 결정 |
| --- | --- |
| 피해 고객에게 주는 보상, 한 고객 합계 10만 원 이하, 장애 보상 합계가 피해 금액 이하 | 승인 |
| 캠페인 쿠폰 한 번 45만 원 이하, 한 장 3만 원 이하, 오늘 쿠폰 합계 150만 원 이하 | 승인 |
| 결제 금액 안의 환불 30만 원 이하 | 승인 |
| 피해 고객이 아닌 사람에게 주는 보상, 결제보다 큰 환불 | 거절 |
| 적어 낸 금액과 계산이 다름, 등록되지 않은 일, 요청 형식 오류 | 자동 거절 |
| 판매자 위험 점수 90점 이상 | 거절 |
| 위 한도를 넘는 큰 금액, 위험 점수 70~89점, 판매자 정산 확정, 자료가 없음 | **사람에게 넘김** |

재무 AI가 응답하지 않으면 사람에게 넘어갑니다.

## 관리자가 할 일: 결정하기

### 1. 카드 읽기

"지금 사람이 결정할 일"의 카드 한 장에는 다음이 있습니다.

- **금액**: 코드가 다시 계산한 금액 (요청한 쪽이 적은 금액이 아님)
- **무슨 일**: 쿠폰 지급, 환불, 판매자 정산 확정 등
- **이유**: 왜 사람에게 넘어왔는지. 예: "한 고객에게 준 보상 합계가 60,000원 — 기준 50,000원 이상"
- **요청한 AI와 남은 시간**: 24시간 안에 결정하지 않으면 **자동으로 취소(멈춤)** 됩니다

### 2. 이럴 땐 이렇게

| 이유 | 보통의 판단 | 확인할 것 |
| --- | --- | --- |
| 금액 기준을 넘음 (쿠폰) | 장애 규모에 맞으면 진행 | 같은 화면의 "장애로 생긴 손실"과 비교. 피해보다 보상이 지나치게 크면 멈춤 |
| 금액 기준을 넘음 (환불 10만 원 이상) | 주문이 맞으면 진행 | 쇼핑몰 관리 화면에서 주문·결제 금액 확인 |
| 적어 낸 금액과 계산이 다름 | **멈춤** | 요청한 AI가 금액을 잘못 적었다는 뜻. 담당자(쿠폰은 마케팅, 환불은 고객지원)에게 알림 |
| 항상 사람이 확인하는 일 (판매자 정산 확정) | 정산 내용이 맞으면 진행 | 판매자, 기간, 금액 확인 |
| 판매자 위험 점수가 높음 | 판매자 정보를 본 뒤 결정 | 서류와 판매자 화면 확인. 애매하면 멈춤 |
| 확인하는 쪽이 응답하지 않음 | 서버가 꺼져 있었다면 멈춤 | 화면 오른쪽 위 "재무 AI 켜짐" 표시 확인 |
| 등록되지 않은 일 | **멈춤** | 처음 보는 일입니다. 담당자(태윤)에게 문의 |

애매하면 **멈춤**을 누르세요. 멈춘 일은 요청한 AI가 내용을 고쳐서 다시 요청할 수 있습니다. 진행은 되돌릴 수 없습니다.

### 3. 결정한 뒤

- [진행]: 그 일이 처리됩니다. 요청한 AI가 같은 요청을 다시 보내면 "처리됨"을 받고 실제로 실행합니다.
- [멈춤]: 그 일은 실행되지 않습니다. 결정은 "최근 결정"에 이름과 시각이 남습니다.
- 24시간 동안 아무도 결정하지 않으면 자동으로 멈춤 처리되고 "자동 취소"로 남습니다.

## 화면의 다른 부분

| 영역 | 무엇을 보나 |
| --- | --- |
| 들어온 요청이 어떻게 처리됐나 | 오늘 요청이 세 갈래로 어떻게 나뉘었는지. 사람 확인 비율이 갑자기 늘면 기준이나 AI 동작을 점검 |
| 장애로 생긴 손실 | 장애별 실패 주문, 피해 고객, 피해 금액, 보상으로 나간 돈, **총 손실** |
| 재무 AI가 다시 계산한 결과 | 재무 AI가 통과시키거나 막은 쿠폰·환불과 그 이유 |
| 처리 내역 | 모든 요청의 처리 방식과 결과 |
| 판매자 관리 | 판매자 입점 심사, 정산 멈춤 결과 |
| 캣북스에서 들어온 처리할 일 | 캣북스 쇼핑몰의 환불·교환·보상 신청 중 돈이 나가기 전인 건. 재무 AI가 결제 금액·이미 환불한 금액·규정 계산으로 확인해 **통과 / 막음 / 사람 확인 필요**로 나눔. 45초마다 자동으로 가져오고, "지금 가져오기"로 바로 가져옴. 재무 AI는 읽기만 하고, 실제 지급은 캣북스의 지급 버튼이 함 |
| 재무 AI가 하는 일 / 사람 확인 기준 | 참고용. 눌러서 펼침 |

## 자주 묻는 질문

**기준(예: 쿠폰 30만 원)을 바꾸고 싶어요.**
화면의 "사람 확인 기준"에서 **"기준 바꾸기 요청"**을 쓰세요. 기준을 고르고 새 값과 이유를 적은 뒤 [재무 AI에게 요청]을 누르면 아래 순서로 처리됩니다.

1. **안전 장치 확인** (코드가 하고, 재무 AI도 담당자도 넘을 수 없습니다)
   - 처음 정한 값의 **절반부터 두 배까지만** 바꿀 수 있습니다. 예: 쿠폰 한 번 30만 원 → 15만~60만 원
   - 사람 결정 마감은 **1시간부터 3일까지만** 정할 수 있습니다
   - 숫자 기준만 바꿀 수 있습니다. AI 판단 켜기·끄기, 허용 경로 목록, 기준 삭제는 지금처럼 담당자(태윤)가 직접 고칩니다
   - 이유는 꼭 적어야 하고 300자까지입니다
   - 범위를 넘으면 바로 **거절**되고 이유가 표시됩니다
2. **재무 AI가 결정** (기준: `ai_review_policy.toml`의 `[threshold_change]`, 사람만 변경)
   - 지금 값에서 **30% 넘게** 바꾸면 → 재무 담당자에게 넘김
   - 기준을 **낮추면**(더 엄격하게) → 바로 바뀜
   - 기준을 **올리면** → 최근 24시간에 그 기준 때문에 멈춘 일이 **3건 이상**일 때만 바뀜. 아니면 "근거 부족"으로 재무 담당자에게 넘김
   - 적어 낸 이유는 기록만 하고 판단에는 쓰지 않습니다 ("무조건 승인해" 같은 글도 소용없습니다)
3. **결과**: "바뀜"이면 바로 다음 요청부터 새 기준이 쓰입니다(기준표 버전이 1 올라감). "재무 담당자 확인 대기"면 담당자가 같은 화면의 [승인]/[거절]로 정합니다. 재무 AI가 응답하지 않아도 담당자에게 넘어갑니다.

바뀐 기준은 지금은 서버를 다시 켜면 처음 값으로 돌아갑니다. 오래 쓸 기준이면 담당자(태윤)에게 `thresholds.toml` 수정을 요청하세요.

**재무 AI가 막은 쿠폰을 그래도 주고 싶어요.**
재무 AI가 막은 건(예: 장애 피해 고객이 아님)은 사람 확인으로 오지 않습니다. 정말 필요하면 마케팅 담당에게 이유를 알리고 다시 요청하게 하세요. 그래도 기준에 걸리면 사람 확인으로 넘어옵니다.

**결정 버튼이 꺼져 있어요.**
결정 권한이 설정되지 않은 것입니다. 데모(목 모드)에서는 ax-frontend 루트 `.env`에 `VITE_SAFETY_HUMAN_TOKEN=human:<이름>`을 넣고 대시보드를 다시 켭니다. 실제 운영에서는 담당자에게 사람용 토큰을 받습니다(`SAFETY_HUMAN_TOKENS`).

**"안전 장치 꺼짐" 또는 "재무 AI 꺼짐"이 보여요.**
서버가 꺼져 있습니다. ax-backend에서 `docker compose -f infra/compose.yml up -d safety finance`로 켭니다. 안전 장치가 꺼져 있는 동안 돈이 나가는 일은 **모두 멈춥니다**(실행되지 않음).

**기록이 사라졌어요.**
지금은 서버를 다시 켜면 기록이 비워집니다. 영구 저장(postgres)은 다음 작업입니다.

**데모용 데이터를 넣고 싶어요.**
ax-backend에서 `uv run python agents/finance/demo/seed_demo.py`를 실행하면 가짜 요청 17건이 들어갑니다(목 모드 전용).

## 캣북스 연결 (읽기 전용)

- 재무 AI는 캣북스 관리자 API를 GET으로만 읽는다: `/api/admin/claims`(신청 목록), `/api/admin/claims/{id}`(영수증), `/api/admin/queue`(지급 대기열). 캣북스의 상태는 바꾸지 않는다.
- 확인하는 것: (1) 줄별 환불·차감·배송비·교환·보상 적립금이 캣북스 규정 계산과 맞는지, (2) 환불이 현금 결제 - 이미 환불한 금액 안인지, (3) 환불 10만 원 이상(안전 장치 기준)이면 재무 AI 재량 한도(30만 원) 안에서만 통과시키고 "실제 지급은 안전 장치를 거쳐야 함"을 붙임. 한도를 넘거나, 영수증이 없거나, 캣북스가 이상 신청(점수 60 이상)으로 표시했거나, 보상 금액이 정해지지 않은 건은 사람 확인.
- 설정: `FINANCE_CATBOOKS_URL`(기본 `http://host.docker.internal:8030`), `FINANCE_CATBOOKS_POLL_SECONDS`(기본 45, 0이면 자동 가져오기 끔).
- 남은 일: 캣북스 지급 버튼(`POST /api/admin/queue/process`)이 지급 전에 ax 안전 장치를 부르게 하려면 캣북스 쪽 변경이 필요하다 (담당 병환/bxbae).
