# 재무 AI 관리자 사용법

담당: 태윤 · 화면: 대시보드 → 상단 메뉴 **재무 AI** (`http://localhost:3001/finance`)
설계 원본: `docs/notes/finance/2026-10-23-finance-redesign.md` (재무 재설계, 2026-10-23)

## 한 줄 요약

재무 AI는 **캣북스의 재무팀**입니다. 결산, 매출·PG 대사, 판매자 정산, 예산·한도 정책, 사후 감사를 맡습니다.
**쿠폰 하나, 환불 하나를 건별로 승인하지 않습니다.** 건별 검사는 안전 장치의 코드 규칙(금액 계산, 기준표 한도)이 하고,
재무는 그 규칙이 쓰는 한도를 *제안*하고 지나간 기록을 전수로 다시 봅니다. 숫자는 모두 코드가 계산하고, AI는 설명 문장만 씁니다.

관리자가 할 일은 화면 맨 위 **"지금 사람이 할 일"** 목록을 위에서부터 처리하는 것입니다.

## 흐름

자동 수집 → 규칙으로 맞추고 분류 → **예외만 사람에게** → 결산·리포트

| 단계 | 누가 | 무엇을 |
| --- | --- | --- |
| 자료 모으기 | 재무 AI | 쇼핑몰 주문·결제·환불·쿠폰·판매자, 안전 장치 기준표·실행 기록 (데모는 가짜 장부) |
| 맞추고 나누기 | 재무 AI (코드 규칙) | 손익 계산, 결제 ↔ PG 정산 대사, 판매자 정산금, 예산 소진율, 감사 규칙 |
| 예외 처리 | **관리자** | 결산 확정, 대사 불일치 메모, 정산 묶음 지급 요청·승인, 감사 의심 건 확인, 한도 변경(기준표 PR) |

## 지금 사람이 할 일

| 할 일 | 어디서 | 어떻게 |
| --- | --- | --- |
| 판매자 정산 N곳 지급 승인 요청 대기 | ③ 판매자 정산 | 내역서를 보고 [정산 묶음 요청]. 보류 사유가 없는 판매자만 묶입니다. 요청은 안전 장치 **보류 큐(C)**로 가고, 지급 승인은 보류 큐에서 사람이 합니다 |
| 판매자 정산 지급 승인 대기 (안전 장치) | 안전 장치 보류 큐 | 판매자·기간·금액을 확인하고 [승인]/[거절]. 10분 안에 결정하지 않으면 자동 거절, 다시 요청할 수 있습니다 |
| 어제 결산 확정 대기 | ① 결산·리포트 | 손익 줄과 분개 미리보기를 보고 [결산 확정]. 이름과 시각이 남습니다 |
| 매출·PG 대사 불일치 N건 | ② 매출·PG 대사 | 건마다 원인을 확인하고 처리 메모를 남깁니다 (예: "PG사에 문의함"). 메모를 남긴 건은 할 일에서 빠집니다 |
| 사후 감사 의심 N건 | ⑦ 내부통제·감사 | 의심 내용과 참조 번호(쿠폰·실행 기록)를 보고 조사합니다 |
| 예산·한도 경보 | ⑤ 예산·한도 정책 | 소진율이 80% 이상이거나 월말 예상이 예산을 넘음. 필요하면 한도 변경을 기준표 PR로 요청 |

결정 버튼(결산 확정, 대사 메모)은 사람 토큰이 있어야 눌립니다. 정산 묶음 요청은 토큰이 없어도 되지만, 지급 승인은 안전 장치에서 사람만 합니다.

## 다섯 개 영역

### ① 결산·리포트
- 일·월 손익: 총거래액(품목 판매가 합계), 판매 수수료 매출(도서 10%, 문구 8%), 쿠폰 비용(회사 부담), 환불, PG 수수료(3.1%), 영업 결과
- 영업 결과 = 수수료 매출 − 쿠폰 비용 − PG 수수료. 환불은 판매자 정산에서 빠지므로 영업 결과에 넣지 않습니다
- 자동 분개 미리보기(차변 합계 = 대변 합계), 쉬운 말 설명(AI가 못 쓰면 정해진 문장. 화면에 "템플릿"으로 표시)
- 장애 손실 리포트(`loss_aggregation`)도 이 영역입니다

### ② 매출·PG 대사
결제 한 건씩 주문 금액 ↔ PG 정산을 맞춥니다.

| 상태 | 뜻 | 할 일 |
| --- | --- | --- |
| 일치 | 금액·수수료 모두 맞음 | 없음 |
| 정산 전 | 판매일 + 2일 지급 예정일이 아직 안 됨 | 없음 |
| 금액 다름 | PG 금액 ≠ 주문 금액 | PG사·주문 확인 후 메모 |
| PG에 없음 | 지급 예정일이 지났는데 PG 정산에 없음 | PG사 문의 후 메모 |
| 수수료 이상 | 수수료가 3.1% 계산과 1원 넘게 다름 | 계약 수수료 확인 후 메모 |

실제 PG가 없어 PG 정산은 **토스 정산 형식의 가짜 자료**이고, 데모용 불일치가 일부러 들어 있습니다.

### ③ 판매자 정산
- 정산금 = 판매액 − 판매 수수료 − 판매자 부담 쿠폰 − 환불. 주 단위(월~일), 기본은 지난주, 지급일은 기간 끝 + 6일
- 보류 사유(하나라도 있으면 묶음에서 빠짐): 처리 중인 환불·교환, 구매 미확정(배송 완료 전) 주문, 위험 판매자 정산 보류, 정산금 0원 이하. 실제 모드에서 클레임 목록을 못 받으면 "확인할 수 없음"으로 보류합니다
- 묶음 상태: 없음 → 요청됨(안전 장치 보류 큐) → 승인됨/거절됨. 거절되면 다시 요청할 수 있습니다
- 안전 장치가 꺼져 있으면 요청이 되지 않고("안전 장치에 닿지 않음") 아무것도 기록되지 않습니다

### ⑤ 예산·한도 정책
- 정책표: 안전 장치 기준표(쿠폰 한 번·한 장·하루, 보상, 환불 한 건, 판매자 위험)와 재무 예산(이번 달 쿠폰 30만 원, 환불 60만 원)
- 소진율과 경보: 정상 / 주의(80% 이상 또는 월말 예상 초과) / 초과(100% 이상)
- 한도 제안: 최근 14일 실제 값의 95%를 기준으로 제안합니다(한 번에 30% 안). **재무 AI는 바꾸지 않습니다.** 바꾸려면 기준표(`safety/src/ax_safety/rules/thresholds.toml`) PR을 사람이 올립니다

### ⑦ 내부통제·감사 (사후 감사, 기본 최근 7일)

| 의심 | 규칙 |
| --- | --- |
| 한도 바로 아래로 쪼개기 | 같은 고객에게 한도의 90% 이상 쿠폰을 1시간 안에 나눠 3장 이상, 또는 한도 바로 아래 환불을 하루에 2번 이상 |
| 같은 고객 반복 환불 | 기간 안에 주문 3건 이상 환불 |
| 같은 고객 쿠폰 중복 | 같은 장애에 같은 고객 보상 쿠폰 2번 이상 |
| 환불률 급변 | 지난 기간의 1.5배 이상이고 1%p 이상 오름 |
| 다시 계산하니 틀림 | 안전 장치를 통과한 쿠폰·환불을 원래 자료로 다시 계산했더니 결제 금액 초과·금액 불일치 |
| 관문 보류·거절 증가 | 기간 안 보류·거절 3건 이상이고 지난 기간의 2배 이상 |

## 바뀐 점 (2026-10-23)

- 쿠폰·환불은 안전 장치에서 **A(바로 실행)**입니다. 한도를 넘거나 적어 낸 금액이 계산과 다르면 지금처럼 사람 확인(C)
- 재무 AI가 쿠폰·환불을 건별로 다시 계산하던 일(`verify_amount`)과 사람 확인 건을 AI가 먼저 결정하던 일(`review_hold`)은 없앴습니다
- 화면에서 "거래별 검증 목록", "AI가 결정한 건 목록", 네 갈래 처리 흐름은 빠졌습니다

## 화면의 다른 부분 (그대로)

| 영역 | 무엇을 보나 |
| --- | --- |
| 재무 AI 테스트 버튼 | 계산 규칙(금액 다시 계산, 결산·대사·정산·예산·감사)과 연결(안전 장치, 쇼핑몰, 데이터 AI, 캣북스)을 점검. 상태를 바꾸지 않음 |
| 장애로 생긴 손실 | 장애별 실패 주문, 피해 고객, 피해 금액, 보상, 총 손실 |
| 캣북스에서 들어온 일 | 캣북스 환불·교환·보상 신청을 규정 계산으로 확인해 **통과 / 막음 / 사람 확인 필요**. 10만 원 이상 환불은 계산이 맞아도 "규칙 확인 통과 / 사람 확인 필요"이고 실제 지급은 안전 장치에서 사람이 승인. 45초마다 자동으로 가져옴 |
| 판매자 관리 | 판매자 입점 심사, 정산 멈춤 결과 |

## 자주 묻는 질문

**결정 버튼이 꺼져 있어요.**
데모(목 모드)에서는 ax-frontend `.env`에 `VITE_SAFETY_HUMAN_TOKEN=human:<이름>`을 넣고 대시보드를 다시 켭니다. 실제 운영은 사람용 토큰(`SAFETY_HUMAN_TOKENS` 또는 `FINANCE_HUMAN_TOKENS`)을 받습니다.

**"확인할 수 없음"이 보여요.**
원천 자료(쇼핑몰, 안전 장치)를 받지 못한 값입니다. 재무 AI는 추정값을 만들지 않습니다. 화면 아래 "받지 못한 자료"에 이름이 나옵니다.

**기록이 사라졌어요.**
결산 확정, 대사 메모, 정산 묶음 상태는 지금은 메모리에 있어 서버를 다시 켜면 비워집니다. 영구 저장은 다음 작업입니다.

**재무 서버를 혼자 띄워 보고 싶어요.**
ax-backend 루트에서 `FINANCE_MOCK=1 FINANCE_CATBOOKS_POLL_SECONDS=0 uv run uvicorn finance_agent.main:app --port 8105` (목 장부는 오늘 날짜 기준 최근 2주치). 정산 묶음을 안전 장치 보류 큐까지 보내 보려면 safety도 목 모드로 띄우고 `AX_SAFETY_URL=http://localhost:8001`을 줍니다. 안전 장치 주소가 없으면 목 모드에서는 바로 "승인됨"으로 보입니다(템플릿 목 동작).

## 캣북스 연결 (읽기 전용)

- 재무 AI는 캣북스 관리자 API를 GET으로만 읽습니다: `/api/admin/claims`, `/api/admin/claims/{id}`, `/api/admin/queue`. 캣북스의 상태는 바꾸지 않습니다.
- 확인하는 것: (1) 줄별 환불·차감·배송비·교환·보상 적립금이 캣북스 규정 계산과 맞는지, (2) 환불이 현금 결제 − 이미 환불한 금액 안인지, (3) 환불 10만 원 이상(안전 장치 기준)이면 계산이 맞아도 사람 확인. 영수증이 없거나, 이상 신청(점수 60 이상)이거나, 보상 금액이 정해지지 않은 건도 사람 확인.
- 설정: `FINANCE_CATBOOKS_URL`(기본 `http://host.docker.internal:8030`), `FINANCE_CATBOOKS_POLL_SECONDS`(기본 45, 0이면 끔).
