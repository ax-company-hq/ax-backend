## 결정과 이유
- **보상 번호(sequence)는 "마케팅이 소비했을 때만" 올린다.** 마케팅 리뷰(재헌)가 짚은 버그: 재무 검증 중(`working`)이면 마케팅은 번호를 쓰지 않는데 support가 올리면 다음 요청이 `SEQUENCE_GAP`으로 막힌다. 소비하는 경우는 지급·재무 거절·보류·실행 실패·마케팅 쪽 검증 시간 초과이고, 검증 중·번호/입력 오류·우리 쪽 타임아웃은 같은 번호로 재전송한다. 같은 사건의 요청은 락으로 한 건씩 처리한다.
- **클레임 판정은 코드, 금액은 입력으로 받지 않는다.** 주문 사실(시드 주문)에서 기간·수량·금액을 계산하고, 사유 설명·메모는 `untrusted`로만 받는다. 규칙 값(7일, 5만 원, 3건)은 시드이며 memory 정책 문서 API가 생기면 교체한다.
- **환불 지급은 이미 등록된 `refund_request`(B, 재무 검증, 10만 원 이상 C)를 쓴다.** 새 지급 액션을 만들지 않았다. 실행되지 않으면 지급 기록도 남기지 않는다. shop-api 환불 API 호출은 TODO.
- **멱등 재생을 중복 검사보다 먼저 한다.** 같은 `idempotency_key` 재요청이 "진행 중 클레임 중복"에 걸리던 결함을 테스트에서 발견해 고쳤다.
- **문의 외 dashboard-api 경로는 목 전용으로 둔다.** 목 모드가 아니면 문의 경로만 support를 부르고 나머지는 503이다. 에이전트 토큰 변수는 `DASHBOARD_API_TOKEN`(템플릿 접두사 규칙)으로 정정.
- **OpenAPI는 PR에 넣지 않았다.** 폴더 가드를 피하고, 머지 후 openapi-export가 sync PR로 갱신한다.
- **인사(hr) 기능 정리 공지에 대한 답변 초안을 작성했다.** 의견 요지: 인계자 질문 화면은 계약 PR 머지 후, 카드 후보 승인은 보류 큐가 아니라 memory `candidate` 상태로, 메뉴는 대시보드 탭 하나로. 채널이 정해지지 않아 **아직 게시하지 않았다**.

## 막혔던 것과 해결
- **훅·가드 충돌**: 백그라운드 세션은 worktree에서만 편집해야 하는데, 폴더 가드 훅(`guard-folder.mjs`)이 worktree 경로를 "사람 전용 경로"로 판정해 어디서도 쓸 수 없었다. 로컬 `.claude/settings.local.json`에 `worktree.bgIsolation: none`을 사람이 직접 넣어 해결했다(PowerShell로 저장, UTF-8 BOM이 붙었지만 동작).
- **GitHub API 속도 제한**: 조직 공용 5,000/시간이 소진되어 `guards`·`prep`·마케팅 리뷰가 코드와 무관하게 실패했다(#97, #98, #95). 실패한 작업만 재실행했고 이후 결과 조회는 최소화했다.
- **스택 PR 주의**: #97·#104처럼 앞선 PR 위에 쌓은 브랜치는 뒤 PR이 먼저 머지되면 앞 PR 내용이 함께 들어간다(#104가 #95·#97을 포함). 다음부터는 의존 PR이 머지된 뒤 dev에서 새로 따는 것이 낫다.
