## 2. planning.md 변경안

### 2장 부서 표 — 인사 행
현재: `| 인사 | 조직 기록, 지식 관리 | 사건 기록(포스트모템), 인수인계 |`
제안: `| 인사 | 조직 기록, 지식 관리, 사람 변화 대응 | 사건·결정 기록, 명부·교대, 인수인계, 온보딩, 발령·퇴직·입사, 계획 비교 |`

### 6장 안전 레이어와 자율성 레벨 — 인사 액션 등급 문단 추가
> **인사 액션 등급.** 카드 쓰기·인수인계 초안·답변·온보딩·변경 요청은 A. 인수인계 확정은 planning이 교차검증하는 B(완성도 기준 미만은 C), 재배치 확정은 담당 공백·중복이 없는지 코드 규칙으로 검증하는 B, 퇴직 확정은 항상 C(사람 승인). 권한 회수·부여는 hr이 실행하지 않고 목록을 각 부서에 전달만 한다.

### 시나리오 A·B의 인사 항목
시나리오 A "6. 인사 — 사건 기록을 회사 기억에 저장"과 B "6. 인사 — 판단 근거 기록"은 그대로 둔다. 사람 변화 흐름은 시나리오 C(제안): "7. **인사** — 담당 변경 요청 → 인수인계 초안·질문 → 확정 → 재배치 검증 → 온보딩"을 덧붙일지 팀과 정한다(필수 범위 밖).
