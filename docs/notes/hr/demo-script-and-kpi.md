# 시나리오 A hr 장면 데모 스크립트와 KPI 수치 (초안)

화면: `uv run --package ax-agent-hr python -m hr_agent.demo` → http://localhost:8114 (개발 전용, 목 모드).
실제 연동 전이라 숫자는 **목 모드·같은 프로세스 기준**이다. 발표에서 쓸 때 "목 기준"이라고 말한다.

## 1. 데모 스크립트 (약 4분)

### 장면 1 — 사건이 끝나면 hr이 기억한다 (시나리오 A 6번, 60초)
1. **1 기록** 탭 → 예시 "결정(이유·대안·근거 있음)"을 고르고 `기록 보내기`.
   - 말: "장애 대응이 끝나면 각 부서가 결정을 hr에 보냅니다. hr은 결정 카드로 정리해 회사 기억에 남깁니다."
   - 보여 줄 것: 결과 `card_created`, 확신도 `high`, 카드에 이유·검토한 대안·근거 참조가 모두 있다.
2. 예시 "결정 없음(기록만)" 전송 → `record_only`. 말: "결정이 없는 기록은 카드를 만들지 않고 기록만 남깁니다."
3. 예시 "근거 없는 결정(후보)" 전송 → 후보 카드, 이유 칸이 "확인할 수 없음". 말: "근거가 없으면 지어내지 않고 후보로 둡니다. 사람이 승인해야 확정입니다."
4. 같은 요청을 한 번 더 보내기 → `duplicate`. 말: "같은 기록이 두 번 와도 카드는 한 장입니다."

### 장면 2 — 다음 장애에서 기억이 일한다 (학습 효과 SCN-L, 60초)
1. 예시 "기각한 안"을 보내 둔다 (결제 서버 캐시 도입안 기각).
2. **2 계획 비교** 탭 → 기본 입력(`결제 서버 캐시 도입`)으로 `비교하기`.
   - 보여 줄 것: 판정 `warn`, `이전에 기각됨`, 근거 카드, **"기각 후 N일"은 코드가 계산**(날짜를 움직여 보려면 시나리오 18을 쓴다).
   - 말: "2차 장애에서 비슷한 제안이 나오면 이전에 기각된 이유를 먼저 알려 줍니다. 숫자는 AI가 쓰지 않고 코드가 셉니다."
3. 영역을 `search`로 바꿔 비교 → `기록에 없음`. 말: "관련 기록이 없으면 판단하지 않습니다."

### 장면 3 — 사람이 바뀌어도 일이 끊기지 않는다 (80초)
1. **3 명부·교대** 탭 → 공백 영역 `inventory`와 교대 공백을 보여 준다.
2. **4 인수인계** 탭 → 인계자 `emp_01` → `초안 만들기`.
   - 보여 줄 것: 진행 중 3건·결정 카드·연락처는 자동으로 채워지고, 빈 항목 질문이 나온다. 완성도는 코드가 계산(예: 40% → 60%).
   - `답변 보내기`로 채우면 100% → `확정 요청` → 확정(B, planning 검증). 말: "완성도 80% 미만으로 확정을 요청하면 보류 큐로 가서 사람이 결정합니다."
3. **5 발령·퇴직** 탭 → 퇴직 요청 → 재배치 확정 → `퇴직 확정(보류 큐)` → 보류 큐(헤더의 "보류 N건" 배지)에서 승인 → 다시 확정.
   - 말: "퇴직은 되돌리기 어려워 항상 사람 승인입니다. 승인 전에는 아무것도 바뀌지 않습니다."
4. **감사 로그** 탭 → 방금 한 일이 시간순으로 남아 있다. 말: "모든 처리는 근거와 함께 기록됩니다."

### 장면 4 — 안전장치 (40초)
- **시나리오** 탭 → `전체 실행`: 26개 시나리오 전부 기대 결과와 일치, 두 번 돌려도 결과가 같음(결정성).
- 시나리오 07(권한 없는 요청자) → `FORBIDDEN_SKILL`로 거절.
- 말: "hr은 판단하지 않고 규칙이 정합니다. 외부에서 온 문구는 지시로 읽지 않습니다."

## 2. KPI 수치 (측정값)

| 지표 | 값 | 측정 방법 |
|---|---|---|
| 자동화된 확인(테스트) | hr 251개 통과 | `uv run pytest agents/hr` |
| 안전 회귀 "잘못 통과" | **0 / 81건** | `tests/test_safety_regression.py`: 권한 없는 요청자·관문 오류/거절/보류·루프·마감·키 누락·우회 시도·인젝션 |
| 결정성 | 시나리오 26개 × 20회 반복, **전부 동일** | `tests/test_fuzz.py` |
| 무작위 입력 | 16,500건에서 오류(500·handler_error) **0건**, 영역당 담당 최대 1명·DB 무결성 유지 | 고정 시드 6개(1,500 + 3,000×5) |
| 결정 탐지 정확도 | 규칙을 만들 때 본 문장 60/60(결정 여부·이유·기각), 규칙을 정한 뒤 따로 쓴 문장 20/20. 처음 보는 문장 기준의 개선 전→후: 이유 16/20→20/20, 기각 18/20→20/20 | `tests/test_decision_samples.py`. 표본이 작고 내가 쓴 문장이라 낙관적일 수 있다 |
| 응답 시간(목, 같은 프로세스) | 조회 p50 5ms·p95 20ms, 기록·계획 비교·인수인계 초안·온보딩 p50 7~8ms·p95 18~25ms | 카드 150장, 150회 반복. 네트워크·LLM 없음 |
| 사람 승인이 필요한 경로 | 퇴직 확정, 완성도 미달 인수인계 | 항상 보류(C) |
| 근거 없는 값 | 항상 "확인할 수 없음", 숫자(완성도·경과 일수·진행률)는 코드 계산 | 테스트로 고정 |
