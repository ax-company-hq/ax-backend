바꿀 글:

```markdown
- **사람보다 규칙과 검토 AI가 먼저 본다** (AI 1차 판단, 13장 결정 22).
  - 요청 자체가 잘못된 건(`amount_mismatch`·`unregistered_action`·`schema_invalid`)은 규칙이 바로 거절한다. `decided_by=auto-rule`이고, 요청 부서가 고쳐서 다시 요청한다.
  - 기준표 `[auto_review]`의 `actions`에 있는 액션(지금 `issue_coupon`·`refund_request`·`seller_review`)은 재무 AI `review_hold`에 먼저 묻는다. 답은 승인·거절·사람에게(`escalate`) 중 하나다. 승인·거절은 `decided_by=finance-ai`로 남긴다.
  - 검토 AI가 사람에게 넘기거나 마감(10초) 안에 답하지 않으면 사람이 결정한다. 목록에 없는 액션(판매자 정산 확정 등)은 항상 사람이 결정한다.
  - 검토 AI도 판단 기준표(코드)로만 결정한다. LLM은 결론을 정하지 않는다.
  - `[auto_review]`는 사람만 바꾼다. 끄면 모든 C 건을 사람이 결정한다.
- 사람에게 넘어온 건은 대시보드가 보여 주고, 해당 부서 담당자가 승인·거절한다. 결정 API는 사람 토큰만 허용한다. 사람에게 넘어온 건은 사람이 최종 결정한다.
- **정해진 시간 안에 결정이 없으면 자동 거절한다** (결정안 2번). 기한은 데모 10분, 운영은 환경변수 `SAFETY_REVIEW_TIMEOUT_SECONDS`로 덮어쓴다(예: 86400 = 24시간). AI 1차 판단은 기한을 바꾸지 않는다. 재무 구성안 보류 큐에 이 규칙을 추가한다.
- **검토자는 액션별로 지정한다** (#190, 계약 #191, 13장 결정 23). 예: `confirm_spec` → hr `check_plan`, `merge_pr` → data + orchestrator. 검토자가 여럿이면 전원 승인해야 통과하고, 거절·사람에게·무응답이 하나라도 있으면 사람이 결정한다. 검토자는 요청 부서와 달라야 한다. 되돌릴 수 없는 액션과 보호 경로(#203)에 걸린 건은 검토자 없이 항상 사람이 결정한다.
```

### E7. `docs/agent-common.md` — 7장, `### 액션 등급 신고` 끝(`pr_allowed_paths` 줄 다음, `## 8.` 앞)에 새 절 추가

추가할 글:

```markdown
### 기준 바꾸기 (실행 중, 재무 AI 결정)

- 기준표 파일은 원래 값이다. 사람만 PR로 바꾼다(#202). 실행 중에는 **숫자 기준만** 바꿀 수 있다 (13장 결정 24).
- 요청: 사람(대시보드) 또는 재무 에이전트. 다른 에이전트는 요청할 수 없다.
- 순서: 안전 장치(코드) → 재무 AI `review_threshold_change` → 적용·거절·사람 대기.
- **안전 장치** (재무 AI·사람 모두 API로는 넘지 못한다. 걸리면 `decided_by=guardrail`로 거절):
  - 바꿀 수 있는 것: 숫자 규칙(`coupon_total` 등)과 `review_timeout_seconds`만
  - 바꿀 수 없는 것: `[auto_review]`, 허용·보호 경로 목록, `verify_timeout_seconds`, 규칙 삭제
  - 새 값은 원래 값의 0.5배 ~ 2배. `review_timeout_seconds`는 여기에 더해 1시간 ~ 3일 안에서만 (데모 10분 기준이면 실행 중에 바꿀 수 없다)
  - 이유 글은 믿지 않는 글로 다룬다
- 재무 AI가 승인하면 바로 적용하고 기준표 버전을 올린다. 거절하면 끝난다. 사람에게 넘기거나 답하지 않으면 사람이 승인·거절한다. 사람이 승인해도 안전 장치를 다시 검사한다.
- 범위 밖으로 바꿔야 하면 사람(태윤)이 기준표 파일을 PR로 고친다.
- 바뀐 값과 결정(`decided_by`: guardrail·finance-ai·사람 이름)은 safety가 기록하고 감사 로그에 남긴다.
- **학습된 C→B (예정, 계약 #191 확정 뒤)** (13장 결정 25):
  - 넓히는 근거는 검토자 승인이 아니다. 그 기준 안에서 머지된 건이 장애·revert 없이 N건·관찰 기간을 채웠는지다.
  - planning이 제안하고, safety가 보호 경로·최대 범위·관찰 조건을 코드로 먼저 검사한다.
  - 안전 장치 범위 안이면 재무 AI `review_threshold_change`가, 범위 밖이면 사람(태윤)이 결정한다.
  - 줄이기·해제는 자동이다. 장애·revert가 연결되면 바로 해제한다.
  - N건·관찰 기간 값은 사람 전용 기준표 파일에 둔다.
  - 보호 경로(#203)에 걸린 변경은 항상 C이고 학습 대상이 아니다.
```

## 5. 이 변경안이 다루지 않는 불일치 (코드 쪽 할 일)

문서를 위처럼 고쳐도 남는 것들이다. docs PR과 별개로 코드 PR에서 처리해야 한다.

1. **`seller_review` 자기 검토 (#110)**: 레지스트리에서 `seller_review`의 owner는 `finance`인데, #110은 `seller_review` C 건을 재무 AI `review_hold`에 묻는다. E4·E5의 "검토자 ≠ 요청 부서"와 맞지 않는다. #110에서 `seller_review`를 `actions`에서 빼거나 다른 검토자(예: data)로 바꾸고, 검토자 = owner면 로드를 거부하는 검사를 넣어야 한다.
2. **검토자 ≠ 요청 부서 검사 없음 (#110)**: B 검증자는 레지스트리가 검사하지만 `[auto_review].reviewer`는 검사하지 않는다(위 1번의 원인). 액션별 검토자(#190) 확장 때 같이 넣는다.
3. **기준 바꾸기 저장 (#124)**: 바뀐 값은 메모리에만 있고 재시작하면 기준표 파일 값으로 돌아간다(코드 TODO: persist). 문서에는 "safety가 기록하고 감사 로그에 남긴다"까지만 적었다. 영구 저장은 후속 작업이다.
4. **마감 변경 범위 (#124)**: 안전 장치가 "원래 값 0.5~2배"와 "1시간~3일"을 둘 다 요구한다. 데모 원래 값 600초면 두 범위가 겹치지 않아 실행 중에 마감을 바꿀 수 없다. 운영(환경변수 86400초)이면 12시간~48시간만 된다. 문서(E7)에는 이 동작 그대로 적었다. 의도와 다르면 코드를 고친다.
5. **학습된 C→B 미구현**: #124는 숫자 기준만 받는다. `LearnedRuleProposal`(액션+경로+규모 구간) 입력, 관찰 조건 검사, N건·관찰 기간 키는 아직 없다(#191 계약 대기). 문서에는 "(예정)"으로 적었다.
6. **기획개발 PR 머지 (결정 7)**: 학습으로 `merge_pr`를 B로 넓히면 13장 결정 7의 "planning `generate_pr`가 만든 PR은 자동 머지 대상에서 뺀다(머지는 사람이 누른다)"와 부딪친다. planning 담당(예진)이 결정 7 변경을 따로 올리기로 했다(#191 댓글). 이 변경안에는 넣지 않았다.
7. **대시보드 요구사항 (DSH-03)**: AI 결정(`decided_by`) 표시와 기준 바꾸기 화면(ax-frontend `feat/threshold-change-ui`)은 DSH-03에 없다. 어긋나지는 않지만(버튼은 여전히 사람 토큰만) 병환 님이 필요하면 DSH 행을 따로 고친다.
8. **이벤트 필드 (6장)**: safety는 보류 결정 이벤트 data에 `decided_by`를 넣어 보내지만(`gate.py`), 6장 카탈로그의 `safety.review_decided` 필드 목록에는 없다. 필드는 공통 계약 쪽(준하) 판단이라 이 변경안에는 넣지 않았다.
