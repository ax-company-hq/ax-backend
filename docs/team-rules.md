## 통신 규칙

모든 부서 간 직통을 허용하되, 안전장치는 공통 템플릿과 안전 레이어에 내장해 모든 에이전트가 강제로 따르게 한다.

- **MCP**: 에이전트가 도구를 쓰는 연결. 예) DejaFix → Zabbix MCP, 재무/정산 → 주문 조회
- **A2A**: 에이전트끼리 일을 맡기는 연결. 예) 통합 에이전트 → 데이터분석에 영향 분석 요청
- **Agent Card 공개**: 각 에이전트는 `/.well-known/agent-card.json`으로 자기 skills를 공개하고, 통합 에이전트와 다른 부서 에이전트 모두 이를 읽어 직접 호출할 수 있다.
- **통합 에이전트**: 판매 사이트의 이벤트를 받아 사건을 판단하고, 부서 에이전트에 일을 나누고, 결과를 취합한다.
- **공통 템플릿**: 모든 에이전트는 같은 템플릿에서 시작한다. 인증·contextId·로그·구조화 출력 검증이 템플릿에 들어 있다.
- **에이전트와 서비스 구분**: 에이전트는 8개(부서 6 + DejaFix 래퍼 + 통합 에이전트). 판매 사이트·안전 레이어·회사 기억·대시보드는 LLM 없이 코드로만 도는 서비스다.

**이관 규칙**: 이관은 통합 에이전트의 일상 업무가 아니라 설계 결함을 알리는 경보다. 이관 시 원문 대신 contextId, 경로, 사유만 큐에 넣고, 통합 에이전트는 비동기로 꺼내 규칙 기반으로 재분배한다. 이관 건수와 경로는 대시보드에 표시하고, 반복되는 경로는 해당 skill 설명을 고쳐 이관률을 0에 가깝게 유지한다.

## Task 규약

사건 하나는 contextId 하나로 묶고, 그 아래 부서별 Task가 생긴다. Task는 A2A 표준 형식을 쓰고, 아래 확장 필드를 함께 실어 보낸다.

### 상태 (A2A 표준)

| 상태 | 뜻 |
| --- | --- |
| submitted | 접수됨 |
| working | 처리 중 |
| input-required | 다른 판단이 필요해 멈춤. 사유 코드로 구분: 다른 부서 판단 / 고객 자료 / 사람 확정·승인 |
| completed | 완료. 정책에 따른 거절도 정상 처리 결과로 여기에 담는다 |
| failed / rejected / canceled | 실행 오류 / 거부(권한·형식·루프) / 취소(마감 초과) |

### 확장 필드 (안전장치가 쓰는 값)

| 필드 | 뜻 | 쓰는 안전장치 |
| --- | --- | --- |
| contextId | 사건 ID, 필수 | 추적, 멱등성, 요청 예산 |
| 요청자 | 직접 쓰지 않고 에이전트 토큰에서 추출 | 에이전트 인증, skill 권한표 |
| 경로 | 지금까지 거친 에이전트 목록. 루프 검사는 새 요청에만 적용 | 루프 거부, 3홉 제한 |
| 마감 시각 | 이 시각까지 응답이 없으면 포기하고 보고 | 타임아웃 |
| 멱등성 키 | contextId + 액션 + 대상 | 중복 실행 거부 |
| 근거 | 결과를 만든 쿼리·데이터·참조 로그 | 근거 첨부, 받는 쪽 점검 |
| untrusted | 외부 입력(문의 내용, 판매자 정보)을 담는 분리 필드, 지시로 해석 금지 | 신뢰 경계 |
| tenant_id (수정) | 고객사, 필수. 값 `shop-demo` | 데이터 분리 |

필드의 정확한 이름(표기 방식 포함)과 위치는 공통 템플릿(준하)과 「에이전트 공통 구성안」 5장에서 확정한다.

## Agent Card

각 에이전트가 `/.well-known/agent-card.json`으로 공개하는 명함이다. 다른 에이전트는 이 목록을 보고 요청하고, 목록에 없거나 권한이 없는 요청은 거부된다. 각자 착수 전에 자기 Agent Card와 액션 등급을 신고한다. 상세 형식은 「에이전트 공통 구성안」 4장을 따른다.

| 항목 | 뜻 |
| --- | --- |
| 에이전트 이름 | planning, support, finance처럼 영문 소문자 하나 |
| 담당자 | 에이전트 담당 팀원 |
| skills | skill 이름, 한 줄 설명, 입력·출력 형식 |
| 액션 등급 | read(상태 변경 없음) 또는 A/B/C |
| 요청 가능 에이전트 | skill 권한표(ACL). 실행 관문이 확인한다 |
| 검증자 | B 등급의 교차검증 주체. 요청 부서와 같으면 안 된다 |
| 주소 | A2A 요청을 받는 주소 |

아래 장치는 공통 템플릿과 안전 레이어에 들어 있어, 모든 에이전트가 따로 만들지 않고도 강제로 따른다 (기획서 3장).

| 구분 | 장치 | 막는 문제 | 우선순위 |

| 통신 구조 | contextId 필수: 모든 요청·로그를 사건 단위로 묶음 | 추적 불가 | 필수 |
| 통신 구조 | 루프 거부 + 홉 제한: 경로에 같은 에이전트가 다시 나오면 요청자에게 에러, 루프 없이 3홉 초과면 통합 에이전트로 이관 | 무한 핑퐁 | 필수 |

| 오류 방지 | 구조화 출력 검증: 응답을 스키마로 검증, 깨지면 재요청 | 형식 오류 | 필수 |
| 오류 방지 | 계산은 코드로: 숫자는 SQL·코드가 산출, LLM은 해석·판단만 | 계산 오류 | 필수 |

| 보안 | skill 권한표(ACL): skill마다 요청 가능한 에이전트 목록, 실행 관문이 확인 | 권한 없는 요청 | 필수 |

**알려진 한계 (설계로만 제시)**

- 동시 충돌: 같은 대상에 서로 다른 액션이 동시에 실행될 수 있다 → 대상 단위 잠금
- 부분 실패: 일부 액션만 실행되고 사건이 중단될 수 있다 → B 등급 액션마다 되돌리기 액션을 정의하는 보상 트랜잭션(saga)

## 자율성 등급

통합 에이전트가 취합한 "실행할 액션"은 모두 안전 레이어를 거치고, 위험도에 따라 등급을 매긴다. 사람 확인은 C 등급 하나로 한정하고, 되돌리기 어렵거나 금액이 큰 액션은 다른 에이전트의 교차검증 또는 보류로 처리한다.

| 등급 | 자율성 | 예시 액션 | 처리 |
| --- | --- | --- | --- |
| A | L3 완전 자율 | 공지 게시, 티켓 생성, 사건 기록 | 바로 실행 |
| B | L2 실행 + 교차검증 | 롤백, 판매자 정산 보류 | 다른 에이전트가 2차 확인 후 실행 |
| C (수정) | L1 보조 | 판매자 영구 정지, 기준 금액 이상 보상, 서버 재부팅·파일 삭제 | 실행 보류 + 근거 리포트 → safety 보류 큐 하나에 등록, 대시보드에서 해당 부서 담당자가 승인·거절, 데모 기준 10분 안에 처리되지 않으면 자동 거절 |

- 각 부서는 자기 에이전트가 하는 액션의 등급을 개발 착수 전에 신고한다.
- B·C 등급 기준의 상당수는 금액 기준이다. 기준표(`thresholds.toml`)는 사람만 기준표 PR로 바꾸고, 재무 AI는 바꿀 값을 제안만 한다 (2026-10-27 수정). 보상 단가·건수 상한은 고객지원 정책표. (수정) 재무 기준표 v1이 원본: 쿠폰 건별 30만·단가 2만·일일 100만 원, 사건당 보상 누적 100만 원, 고객당 보상 5만 원 이상이면 C. 모두 시작값이며 테스트하며 조정한다.
- (수정) B 등급의 검증자는 요청 부서와 달라야 한다 (자기 검증 금지).
- 등급별 처리 결과와 차단 건수는 대시보드와 감사 로그에 남긴다.
- 등급은 규칙(기준표)이 정하고 LLM이 정하지 않는다. 등록되지 않은 액션은 C로 처리한다 (DejaFix 규칙).

## 역할 분담과 공통 산출물

1인분 = 부서 에이전트 1개 + 공통 모듈 1개로, 6명 모두 비슷한 작업량(체감 5점)에 맞춘다 (기획서 7장). 공통 모듈 담당이 그 모듈의 규격도 책임진다.

| 담당 | 부서 에이전트 | 공통 모듈 | 묶은 이유 |
| --- | --- | --- | --- |
| 준하 | 인사 | 통합 에이전트 + 공통 템플릿 | 템플릿을 만든 사람이 허브도 만들어야 규격이 어긋나지 않음 |
| 재헌 | 마케팅 | 판매 사이트 | 상품 데이터의 주인이 사이트의 주인, 공지 배너도 직접 연결 |
| 병환 | 고객지원 | 오케스트레이션 대시보드 | 프론트 성향 작업, 문의 위젯 포함 |
| 재현 | 데이터분석 | 회사 기억 | 저장·검색(임베딩)은 데이터 담당, 기록 쓰기는 인사 에이전트 |
| 예진 | 기획개발 | DejaFix A2A 연동 | 장애 원인이 배포인 경우가 많아 한 사람이 흐름을 쥠 |
| 태윤 | 재무/정산 | 안전 레이어 | 등급 기준 상당수가 금액 기준 |

**모두 동일하게 지는 공통 산출물**

- 자기 에이전트의 Agent Card + 액션 등급 신고
- 단독 테스트 시나리오 1개 (통합 에이전트 없이 A2A 요청만으로 동작 증명)
- 데모 시나리오에서 자기 구간 책임
- 발표 슬라이드 1장 (As-Is → To-Be)
